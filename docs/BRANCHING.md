# 分支流程

本仓库采用轻量 Git Flow，确保一天范围内仍能保留可回溯的阶段结果。

## 长期分支

- `main`：可发布状态，只接受从 `develop` 合并的已验证版本。
- `develop`：下一版本集成状态，只接受功能分支和修复分支。

## 临时分支

- `feature/<name>`：单一功能或单一阶段。
- `fix/<name>`：验收中发现的问题。
- `docs/<name>`：独立文档调整。

## 提交流程

1. 从 `develop` 创建临时分支。
2. 在分支内完成实现、检查和阶段日志。
3. 使用 Conventional Commits 提交。
4. 以 `--no-ff` 合并回 `develop`，保留功能边界。
5. 完成完整构建与浏览器验收后，将 `develop` 以 `--no-ff` 合并到 `main`。
6. 发布状态使用语义化标签记录。

## 提交类型

- `feat`：用户可见功能
- `fix`：问题修复
- `docs`：文档或内容说明
- `style`：不改变行为的视觉调整
- `refactor`：不改变行为的结构调整
- `test`：测试与验收资产
- `chore`：工具链和仓库维护

禁止直接在 `main` 开发功能，禁止将未通过检查的状态合入 `main`。
