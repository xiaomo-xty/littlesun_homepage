# v0.3 交互与动态世界设计方案

- 状态：待确认
- 基线：`v0.2.0`
- 方案分支：`docs/v0.3-interaction-plan`
- 视觉参数：`DESIGN_VARIANCE 7 / MOTION_INTENSITY 8 / VISUAL_DENSITY 5`

## 1. 设计结论

v0.3 采用一条明确方向：把主页做成一个有生命感的技术世界，同时继续让“人”处于叙事中心。

- 卡牌是作品的可玩载体，不扩散成整站游戏 UI。
- 项目区左侧成为与当前卡联动的“牌组侧板”，承担问题、过程和证据。
- 全站使用可重复触发的章节入场与退场，不劫持滚动，不重置用户状态。
- 背景改为单一固定渲染世界，以 WebGPU 为主路径，WebGL2 为降级路径，静态 CSS 为最终兜底。
- 程序化生物使用抽象的“数据鳐”形态，提供生态感，但不成为吉祥物或二次元角色。
- 后处理只作用于背景画布，不处理 DOM 文字、按钮和图片。

这不是把更多效果堆到页面上，而是将信息层、交互层和环境层分开控制。任何时候，姓名、个人叙事和真实证据都必须比特效更清楚。

## 2. 当前状态审计

### 2.1 卡牌切换为何显得顿

当前 `ProjectDeck.tsx` 使用五段阶段状态和固定定时器：

1. `covering`：盖回卡背。
2. `retracting`：收回牌堆。
3. `drawing`：抽取下一张。
4. `revealing`：翻到正面。
5. `idle`：恢复交互。

从 `260ms`、`500ms`、`810ms` 到 `1160ms` 的多个定时点串联动画。与此同时，主卡按项目 ID 重挂载，位移和翻转又使用弹簧收敛。固定等待、组件重挂载、弹簧尾段和层级切换叠加后，会产生两类主观卡顿：

- 阶段之间存在短暂停顿，速度曲线不连续。
- 动画尚未视觉完成时，状态和 z-index 已经切换。

因此只替换某一个 `ease` 不足以解决问题，必须同时重构时序来源和卡牌槽位。

### 2.2 章节动画为何不能重播

当前项目发牌使用 `useInView(..., { once: true })`，并通过 `dealStartedRef` 永久阻止第二次触发。其余章节主要依赖静态布局或局部 hover，没有统一的进入、离开和重新进入协议。

### 2.3 背景为何存在感不足

当前有两套独立背景：

- Hero 使用 Three.js `WebGLRenderer`。
- 全页环境使用 Canvas 2D。

它们不能共享场景状态、指针力场、章节参数或后处理。全页环境的线条透明度和位移幅度偏低，随机变化周期较长，鼠标不动时难以察觉生命感。

### 2.4 红框区域的问题

红框区域并非单纯“空”，而是信息没有形成反馈闭环：筛选和长列表只负责选卡，选中之后没有继续解释这张卡为何重要。与此同时，问题、过程和证据被藏进卡面详情层，桌面左侧的阅读空间没有发挥作用。

## 3. 动态层级与预算

页面只保留三类动态，每类承担不同职责。

| 层级 | 职责 | 强度 | 约束 |
| --- | --- | --- | --- |
| 信息层 | 章节入场、文字与内容切换 | 中 | 只用透明度、位移、裁切，不能晃动正文 |
| 交互层 | 卡牌、按钮、链接的直接反馈 | 高 | 必须由用户动作触发，响应快且可预测 |
| 环境层 | 几何、粒子、数据鳐、后处理 | 中高 | 始终在正文后方，自动避让内容安全区 |

同一时刻只允许一个高强度焦点。项目卡正在切换时，背景只响应一个较弱的脉冲；章节正在入场时，环境不同时制造大幅镜头变化。

## 4. 全站 Motion 架构

### 4.1 统一曲线

主流程使用显式 cubic Bezier tween，弹簧只保留给 hover、按压和末端微回弹。

| 用途 | cubic Bezier | 体感 |
| --- | --- | --- |
| 抽牌与主要入场 | `[0.16, 1, 0.3, 1]` | 快速响应，平稳落位 |
| 卡面翻转 | `[0.65, 0, 0.35, 1]` | 中段明确加速，具有实体翻面感 |
| 收牌与退场 | `[0.4, 0, 1, 1]` | 离开果断，不拖尾 |
| 章节揭示 | `[0.22, 1, 0.36, 1]` | 柔和但不松散 |

禁止用多个 `setTimeout` 猜测动画结束。卡牌流程使用 Motion animation controls、序列和完成回调推进状态。

### 4.2 可重复的章节边界

建立一个轻量 `RevealBoundary`，只负责视口状态，不把每个章节改造成 React 大组件。

- `once: false`。
- 章节进入有效视区时播放入场。
- 章节完全离开后等待 `420ms`，才允许下一次重新入场。
- 阈值设置进入和离开迟滞，避免在边缘来回滚动时闪烁。
- 从页面上方或下方重新进入都能播放，但方向保持克制。
- 退场时长约为对应入场的 `55%` 到 `70%`。
- 退场只改变透明度、`transform` 和 `clip-path`，不触发布局重排。
- 章节内部状态必须保留。项目区重新进入时继续展示当前卡和当前筛选，不回到 SceneScope。
- 不做滚动劫持、强制吸附或横向滚动叙事。

### 4.3 各章节动作

| 章节 | 入场 | 退场 | 重播时保留 |
| --- | --- | --- | --- |
| Hero | 身份、介绍、人物视觉分层落位；背景从低能量状态启动 | 内容轻微上移并淡出 | 打字机当前句和主题 |
| 关于我 | 叙事列依次揭示，技术轴沿真实阅读方向生长 | 技术轴先收，正文后退 | 无交互状态 |
| 技术带 | 像素文字做短距离裁切滑入 | 快速裁切离开 | 无 |
| 项目 | 侧板先进入，随后当前卡与后续卡依次发牌 | 卡组盖回背面并略微收拢 | 筛选、当前卡和链接焦点 |
| 文章 | 行项目以短 stagger 和方向裁切进入 | 行项目依次淡出 | 无 |
| 生活 | 图片使用小幅错位和受限视差 | 视差归零后淡出 | 无 |
| 联系 | 文案上升，色场比正文慢半拍稳定 | 文案先离开，色场后收 | 主题 |

`prefers-reduced-motion` 下取消位移、翻转、裁切和 stagger，只保留近乎即时的透明度状态变化。

## 5. 卡牌切换重构

### 5.1 槽位而不是重挂载

卡组维持固定的可见槽位：当前牌、后一张、后两张。数据数量仍不封顶，但动画节点不会因为 `selected.id` 改变而整体重挂载。

- 当前牌始终占用主槽位。
- 后两张保持可见并可点击。
- 切牌时只交换槽位所绑定的数据和视觉状态。
- z-index 在明确的翻面中点切换，不在弹簧尚未稳定时切换。
- 正反面共享同一个 3D 容器和尺寸基准。

### 5.2 单次切牌时间线

目标总时长：`760ms` 到 `850ms`，推荐基准 `820ms`。

| 时间 | 动作 |
| --- | --- |
| `0-180ms` | 当前牌正面翻至卡背；指针倾斜先在 `80ms` 内归零 |
| `120-580ms` | 旧牌沿弧线回到牌堆，同时下一张可见后牌向主槽位移动 |
| `420-820ms` | 新牌从卡背翻到正面，侧板内容同步切换并产生一次像素脉冲 |

三段有意重叠，避免“盖完、停、收完、停、再抽”的机械感。位移使用二维关键帧形成弧线，翻转使用专用曲线，不用大位移弹簧。

交互期间不并发播放多个切牌序列，但接受至多一个待处理意图。用户快速再点一次时，下一次操作被排队，不会被悄悄丢弃，也不会一次跳过两张。

### 5.3 初次发牌与重新入场

- 初次进入：后两张和主牌以 `120ms` stagger 从同一牌库源点发出。
- 重新进入：只重新发出当前牌和它后面的可见牌，不改变选择。
- 向上离开：卡牌盖回并收拢到后方。
- 快速滚动越过项目区时允许跳过完整发牌，只显示稳定终态，避免追赶动画。

### 5.4 微交互

- Hover 倾斜限制在 `rotateX 3.5deg / rotateY 4.5deg` 以内。
- 按下缩放不低于 `0.97`，避免廉价的剧烈压扁。
- 卡牌落位允许一次不超过 `6px` 的微回弹。
- 粒子只在翻正中点出现一次，并与卡牌主题色一致。
- 键盘方向键、后牌点击、按钮和触摸滑动继续支持同一套状态机。

## 6. 项目区牌组侧板

### 6.1 桌面布局

红框区域改造成一个不套卡片外框的侧板：

```text
┌─────────────────────────────┬───────────────────────────┐
│ WORK DECK + 项目区标题      │                           │
│ [全部 项目 经历 开源 方向]  │       可玩的主卡牌         │
│                             │       + 后两张卡背         │
│ 当前项目叙事                │                           │
│ 01 问题                     │                           │
│ 02 过程                     │                           │
│ 03 证据                     │                           │
│                             │                           │
│ 01 SceneScope  02 C++ ...   │       上一张 / 下一张      │
└─────────────────────────────┴───────────────────────────┘
```

侧板从上到下只有三层：

1. 筛选条。
2. 当前项目的“问题 / 过程 / 证据”叙事。
3. 紧凑的牌组轨道与真实序号。

当前项目切换时，旧内容先用 `120ms` 裁切退场，新内容在卡牌移动到中点后用 `220ms` 揭示。叙事与卡牌动作形成同步，而不是两块互不相干的界面。

### 6.2 卡牌与侧板的职责

- 卡牌保留卡面作品图、类型、状态、属性、技术标签和真实链接。
- 问题、过程和证据的完整内容移到桌面侧板。
- 卡牌 hover 不再打开覆盖大半卡面的详情层，而是高亮侧板中对应的叙事条目。
- GitHub、Demo、案例文章有真实 URL 时才显示可点击动作。
- 不使用虚构评分、战力、稀有度、进度条或 RPG 数值填空间。

### 6.3 移动端

- 顺序为筛选、卡牌、牌组轨道、当前项目叙事。
- 叙事放到卡牌下方，使用单开 accordion，默认展开“问题”。
- 触摸切牌不依赖 hover。
- 后牌露出宽度至少 `28px`，但不能造成水平溢出。
- 链接按钮保持独立点击区，不与拖动手势冲突。

## 7. WebGPU 优先的动态世界

### 7.1 渲染路径

v0.3 将 Hero 的 WebGL 画布和全页 Canvas 2D 合并为一个固定背景世界。

```text
场景状态 + 指针输入 + 章节状态
              ↓
      数据鳐与几何力学模拟
              ↓
 Three.js WebGPURenderer + TSL 节点材质
              ↓ 初始化失败
     WebGL2 fallback backend
              ↓ 仍失败
        静态 CSS 背景
```

主路径使用当前 Three.js `0.179.1` 已提供的 `WebGPURenderer`。该渲染器本身具备 WebGL2 fallback backend，适合在不引入第二套场景实现的前提下优先使用 WebGPU。

- 先检测安全上下文和 `navigator.gpu`，但最终以 renderer 初始化结果为准。
- WebGPU 异步初始化期间显示静态背景，不能出现透明白屏或布局闪烁。
- 运行时记录实际 backend，便于 QA 确认没有误走 fallback。
- 渲染、模拟、场景参数和 DOM 桥接拆开，后续可将模拟或后端替换为 Rust + wgpu/Wasm。
- 本轮不同时维护两个 WebGL/WebGPU canvas，也不引入刚体物理引擎。

### 7.2 章节驱动的同一世界

画布固定在页面后方，章节只平滑调整场景参数，不重新创建 renderer。

- Hero：空间较开阔，几何层次最明显，数据鳐处于探索状态。
- 关于我：几何沿技术轴组织，运动转为稳定轨道。
- 项目：卡牌事件向背景发送一次小幅冲击波，粒子短暂聚拢后散开。
- 文章：背景减速并形成扫描方向，保证长文本阅读。
- 生活：形态更流动、色彩稍活跃，但不引用动画角色素材。
- 联系：环境能量逐渐收束，突出行动入口。

章节之间通过 `1.2s-1.8s` 参数插值过渡，不做镜头硬切。

### 7.3 数据鳐

数据鳐是由节点、低面数薄片、柔性带和像素尾迹构成的抽象程序化生物，不使用受版权保护的角色，也不做明显动漫脸或吉祥物表情。

它持续模拟以下状态：

- 位置、速度、朝向和能量。
- 躯干节点之间的弹性约束。
- 尾迹长度、亮度和离散像素密度。

合力模型：

```text
F = 漫游场 + 指针场 + 几何避障 + 内容安全区排斥 + 边界力 + 事件脉冲
```

行为规则：

- 鼠标静止或离开时，使用低频 curl noise 漫游，不停在固定循环轨迹上。
- 鼠标缓慢移动时靠近并绕行，像在观察指针。
- 鼠标快速扫过时受到排斥，躯干先偏转，尾迹随后跟上。
- 指针点击产生很弱的径向波，不抢夺按钮点击反馈。
- 接近几何时转向或掠过；接触边缘时让对应几何产生一次阻尼摆动。
- 抽牌时收到来自牌组方向的小冲量，并留下短暂像素尾迹。
- 从 DOM 获取标题、正文、按钮等安全区矩形，在屏幕空间施加软排斥，避免穿过主要文字。

模拟采用固定时间步长的半隐式 Euler 或等价稳定积分，限制单帧补步次数。这里需要的是可控的转向和软碰撞，不需要重型物理引擎。

### 7.4 几何与粒子

当前背景的运动幅度提高，但保持低频和连续：

- 大几何位移幅度约 `40-110px`，周期 `8-18s`。
- 缩放范围约 `0.84-1.18`，旋转范围不超过 `10deg`。
- 粒子大小 `1-5px`，亮度和形态使用随机目标缓动，不做逐帧白噪声抖动。
- 指针附近形成力场偏移，离开后通过阻尼回归，而不是立即归零。
- 珊瑚红只用于极少量事件粒子，常态仍以偏蓝和冷白为主。

这些数值是设计上限，不要求所有对象同时达到上限。

## 8. 后处理

后处理通过 Three.js WebGPU/TSL 共用管线完成，只处理背景 render target。

推荐固定顺序：

1. 较低分辨率场景渲染，并清晰上采样。
2. 仅针对高亮粒子和数据鳐边缘的轻量 selective bloom。
3. 指针附近极小范围的局部折射或扰动。
4. 蓝噪声或有序抖动，统一像素与几何质感。
5. 极轻的暗角、对比压缩和色调映射。

明确禁止：

- 全屏模糊。
- 强色差和持续镜头抖动。
- 霓虹泛光覆盖大面积背景。
- 对 DOM 文字、照片、按钮做折射或颗粒处理。
- 用后处理掩盖本身过密的场景。

默认效果应能在静止截图中增加深浅层次，在实际运动中看见生态变化，但关闭后处理后场景仍然成立。

## 9. 性能、可访问性与降级

### 9.1 三层运行档位

| 档位 | 条件 | 行为 |
| --- | --- | --- |
| 完整 | WebGPU 可用、非省流、性能正常 | 完整数据鳐、粒子、选择性 bloom、局部扰动 |
| 平衡 | WebGL2 fallback、移动端或性能下降 | 减少粒子和节点，关闭局部扰动，降低 bloom 分辨率 |
| 静态 | reduced motion、save-data、初始化失败 | 静态几何与颜色场，无生物运动和章节位移 |

### 9.2 运行约束

- DPR 上限：桌面 `1.5`，移动 `1.25`；性能下降时降到 `1.0`。
- 后处理 render target 可按视口以 `0.65-0.8` 比例渲染。
- 隐藏标签页立即暂停，恢复时重置时间差，禁止模拟跳跃。
- renderer 和场景全站只创建一次；组件卸载时完整释放 GPU 资源。
- 通过滚动章节改变参数，不在 `scroll` 事件中逐帧做布局读取。
- DOM 安全区只在 resize、内容变化或章节切换时更新。
- 持续监测帧时间，连续超预算时降低粒子、尾迹和后处理等级。
- Canvas 设置 `aria-hidden="true"`，所有信息和链接仍由语义 DOM 提供。
- 章节动画不能改变键盘焦点；切牌完成后焦点留在对应可见控件。

目标：桌面常见设备维持 `55-60 FPS`，移动端维持至少 `40-45 FPS`。这些是验收目标，不作为对外宣传的性能数据。

## 10. 实施阶段与分支流程

确认本方案后，严格从更新后的 `develop` 顺序建立分支。每一阶段先检查和记录，再以 `--no-ff` 合并回 `develop`。

### 阶段 1：Motion 基础与卡牌时序

分支：`feature/motion-foundation`

- 建立曲线 token 和可重复 `RevealBoundary`。
- 将卡牌从 timeout 状态机改为完成回调驱动的固定槽位序列。
- 验证重复入场、状态保持、键盘和 reduced motion。

### 阶段 2：项目侧板

分支：`feature/project-sideboard`

- 将问题、过程和证据移入桌面侧板。
- 建立紧凑牌组轨道和同步内容切换。
- 完成移动端 accordion 与手势冲突检查。

### 阶段 3：统一 WebGPU 动态世界

分支：`feature/webgpu-ambient-world`

- 合并现有两套背景。
- 接入 WebGPU 主路径与 WebGL2/静态降级。
- 完成几何力场、数据鳐、章节参数和内容安全区。

### 阶段 4：后处理与性能调节

分支：`feature/background-postprocess`

- 接入节点式 bloom、扰动、抖动和色调控制。

## 11. 验收标准

### 卡牌

- 单次切换在 `760-850ms` 内结束，没有可感知的空等阶段。
- 切换中的速度连续，旧牌确实翻回卡背并回到牌堆。
- 后两张始终可见，选择后按正确顺序补牌。
- 连续输入不跳牌、不丢失超过一个待处理意图、不产生重叠动画。
- 正反面边界一致，切换期间无文字重排和页面位移。

### 章节

- 每个主要章节连续离开并重新进入三次，入场均可重播。
- 阈值附近滚动不闪烁、不反复触发。
- 项目筛选、当前卡和键盘焦点在重播后保持。
- reduced motion 下不出现平移、翻转、裁切或持续粒子动画。

### 项目侧板

- 桌面红框区域被当前项目叙事和紧凑牌组轨道有效使用。
- 侧板与卡牌在同一切牌时间线上同步，不显示前后两个项目的混合信息。
- 移动端叙事位于卡牌后方且可单手展开，无水平溢出。
- 只有真实 URL 生成链接，缺失内容继续使用明确占位。

### 动态世界

- 支持设备实际使用 WebGPU backend，并留下可验证的运行标记。
- 强制 WebGPU 初始化失败时能进入 WebGL2，再失败时能进入静态背景。
- 鼠标静止 `10s` 内可明显观察到位置、形态、大小或亮度变化。
- 数据鳐能对慢速指针、快速指针、几何和抽牌事件作出不同反应。
- 数据鳐不穿过主要标题、正文和按钮安全区。
- 浅色和深色主题均有可见层次，但正文对比度不依赖背景。
- 后处理关闭后页面仍成立，开启后不影响 DOM 清晰度。

### 工程质量

- `bun run check` 无错误、警告和提示。
- `bun run build` 成功。
- 1440 x 900 与 390 x 844 无水平溢出、文字裁切和不合理重叠。
- 控制台无 warning/error，切换主题和页面可见性后无 GPU 资源泄漏迹象。
- 博客项目及其现有未跟踪文件保持不变。

## 12. 明确非目标

- 不把个人主页改成完整卡牌游戏。
- 不让数据鳐成为品牌主体或替代真实人像。
- 不引入受版权保护的 Minecraft、塞尔达或动画角色素材。
- 不引入重型刚体物理引擎。
- 不在本轮切换到 Rust + wgpu/Wasm 生产实现。
- 不建设通用动画设计系统或独立组件库。
- 不添加虚构项目、虚构数据、虚构链接或未发生的开源贡献。
- 不修改博客项目。

## 13. 需要保持的边界

- 原始的一天范围已经由 v0.1/v0.2 完成；v0.3 是独立增强版本，按上面的五阶段推进，不假装是一次小修。
- WebGPU 是优先路径，但可访问性和可用性优先于展示技术栈，因此 fallback 不是可选项。
- 如果背景与正文竞争注意力，先降低 bloom、粒子密度和生物亮度，而不是给正文增加更多面板。
- 如果移动端不能同时承受完整后处理和稳定交互，优先保留卡牌与叙事，主动降低背景档位。

确认本方案后再开始阶段 1；本分支不包含任何页面实现改动。
