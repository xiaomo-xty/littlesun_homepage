# v0.12 水母牵引与个人视觉舞台

## 目标

- 将首次进入从计时器驱动的整页上浮改为可等待、可验证的“水母牵引 + 海流托举”编舞。
- 将 Hero 右侧的大型静态占位改为承载人物、工作现场和个人作品的可扩展视觉入口。
- 保留个人叙事优先级，不把首屏改成技术仪表盘、产品官网或通用玻璃卡片。

## 开场编舞

1. 加载门等待背景后端发出 `homepage:ambient-ready`。
2. 页面进入 `ambient`，完整背景先独立展示，正文保持 `inert` 和不可见。
3. 前景水母从视口下方进入，触手先伸展并建立短暂张力。
4. 页面进入 `entering`，海流曲线向上扫过；导航、Hero 叙事和视觉舞台分别从不同高度缓入。
5. 水母继续向上游离并淡化为像素余光，背景后处理回到阅读态。
6. 所有 `Animation.finished` 完成后进入 `ready`，清理临时样式并恢复完整交互。

实现使用 Web Animations API，只动画 `opacity` 与 `transform`。正文不是一个整体长图层，首屏三个层级独立进入；背景就绪后至少经过两个绘制帧才启动编舞，避免 WebGPU 初始化把状态压在同一帧。`4.8 s` 故障保护只负责启动快速版本，不绕过最终可交互状态。

## 个人视觉舞台

`HeroVisualStage.tsx` 是独立 React 交互岛，当前包含三个明确占位模式：

- 人物：自然、清晰、不过度摆拍的个人照片。
- 现场：真实开发环境、调试过程或工作状态。
- 作品：SceneScope 或其他作品中最能说明问题的一帧。

每个模式预留 `src` 与 `alt`，未来接入真实素材时不改变组件结构。桌面支持按钮、左右方向键、指针低幅度视差；触摸设备支持水平滑动。持续指针坐标由 Motion value 与弹簧管理，不进入 React state。

舞台使用一个主取景面、两层结构深度和底部模式轨道，不堆叠额外信息卡。三个模式只改变内部取景框比例、图标和说明；没有真实素材前始终显示“待替换真实素材”，不伪造人物、场景或作品证据。

## 响应式与降级

- `1280 x 720` 下模式轨道与图注完整处于首屏内，并保留下一区块的视觉提示。
- `390 x 844` 下舞台变为稳定单列，模式按钮和箭头保持完整，不产生横向滚动。
- `prefers-reduced-motion` 跳过水母装置，只执行短淡入；舞台关闭倾斜和装饰动画。
- `prefers-reduced-transparency` 使用不透明页面底色，关闭舞台模糊。
- WebGPU、WebGL2 和 static 后端共享同一进入状态机。

## 验收基线

- 首次重载的状态时间实测为：`loading 0.98 s -> ambient 2.66 s -> entering -> ready 4.41 s`。
- 深浅主题均保持正文与舞台标签对比，背景不穿透文字安全区。
- 舞台按钮、键盘切换、移动端触摸布局和未来真实图片分支均保持语义结构。
- 姓名、人像、简历、邮箱与未完成作品链接继续使用明确占位。
