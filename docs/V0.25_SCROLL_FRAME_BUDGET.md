# v0.25 Scroll Frame Budget

## Goal

Improve scroll and interaction smoothness without reducing any approved visual effect, organism count, particle count, motion amplitude, or the fixed `60 Hz` simulation rate.

## Review Findings

- Dolphin deformation sampled a newly allocated position, tangent, normal, and frame object for every vertex on every rendered frame. The full model has about 815 vertices, producing roughly 195,600 short-lived objects per second at 60 FPS.
- The previous `60 FPS` render cap aliased against common 90 Hz and 144 Hz display intervals. It could settle near 45 FPS and 48 FPS respectively, creating regular visual judder even when CPU and GPU work stayed inside budget.
- Hero idle parallax and project-card idle parallax remained subscribed to Motion's global frame loop while offscreen. Their callbacks returned early, but the subscriptions and scheduling remained active.
- The Hero typewriter timer and several infinite CSS animations continued while their sections were offscreen.
- Section transitions repeatedly queried motion descendants and rewrote unchanged state and index attributes.
- Section transitions could mutate SSR markup inside `client:visible` React islands before hydration, causing React mismatch warnings when projects or articles entered the viewport.
- The ambient runtime wrote diagnostic datasets every `250 ms` during normal visits even though only `?debug=1` consumed them.
- Offscreen Hero and project surfaces retained backdrop-filter and persistent `will-change` hints.

## Decisions

### Allocation-free dolphin deformation

The renderer now precomputes each vertex's spine segment, interpolation amount, longitudinal extension, and normal factor once. Each frame updates only seven cached spine segment frames, then writes directly into the existing Float32 position buffers.

The fixed-step spine solver receives a reusable Float64 angle workspace instead of creating `slice().map()` arrays. Tests compare cached deformation against the reference sampler at Float32 output precision and compare workspace-driven simulation against the original path point by point.

### Display-synchronized rendering

The simulation remains fixed at `60 Hz` with accumulator catch-up limits and interpolation. Rendering now follows `requestAnimationFrame` at the display cadence, eliminating divisor aliasing on 90/120/144 Hz panels. Motion speed and physical behavior remain frame-rate independent.

### Visibility-owned motion

- Hero idle parallax creates an RAF only while the Hero section is visible.
- Project idle parallax creates an RAF only while the project stage is visible, ready, not transitioning, and not showing details.
- Typewriter timers pause offscreen and continue from their current phrase on return.
- Hero sweep, section guides, typewriter caret, contact pulse, and card material sweep run only while their owning section is visible.
- Offscreen Hero/project blur layers and persistent composition hints are released, then restored before the content becomes visible.

### Stable reveal and hydration lifecycle

Section motion descendants and their stagger indexes are cached once. Unchanged presence states do not rewrite DOM or dispatch duplicate events.

Unhydrated Astro islands are tracked separately. Reveal attributes are deferred until React finishes taking ownership, then the current section state is applied. The manually hydrated ambient root also removes its leading whitespace node, allowing React to reuse the SSR ocean instead of regenerating it.

### Production-silent telemetry

Normal visits no longer update ambient telemetry datasets or create diagnostic timers. `?debug=1` adds render FPS, average/max frame interval, over-budget frame count, simulation tick, backend, and runtime state for field diagnosis.

## Verification

- `bun test`: 46 passed, 0 failed.
- `bun run check`: 32 files, 0 errors, 0 warnings, 0 hints.
- `bun run build`: 2 static routes generated.
- Desktop WebGPU clean-load sampling: `59.9-60.0 FPS`, `16.67-16.69 ms` average, `16.7-16.9 ms` maximum, 0 frames above `20 ms` across repeated scroll samples.
- Mobile `375 x 844` WebGPU sampling: balanced quality, `59.9 FPS`, `16.69 ms` average, `16.80 ms` maximum, 0 frames above `20 ms`, and no horizontal overflow.
- Hero, projects, and articles were traversed in both directions. Offscreen animation state paused and resumed correctly.
- Fresh development-cache runs produced no hydration, WebGPU, warning, or error console entries.

## Scope Boundary

No visual element, background organism, particle, card effect, glow, parallax range, reveal transition, or simulation rule was removed or reduced. The optimization changes ownership, allocation, scheduling, upload cadence reuse, and offscreen lifecycle only.

The controlled browser session ran at 60 Hz. The 90/120/144 Hz aliasing path is removed structurally, but a final subjective check on the target high-refresh and lower-power physical devices remains useful before deployment.
