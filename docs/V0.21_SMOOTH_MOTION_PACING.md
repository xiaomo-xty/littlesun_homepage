# v0.21 平滑运动节奏

## 目标

- 消除首次加载编舞中仍可感知的顿挫，不改变水母蓄力、冲击、牵引和释放的叙事。
- 降低牵引阶段的主线程与合成负担，同时保留 WebGPU 优先和固定 `60 Hz` 仿真。
- 分别为桌面与移动端选择成本更低的页面合成方式。

## 根因

v0.20 已经让 `impulse` 与 `tow` 的位置和速度连续，但两个分段贝塞尔在交界处仍有明显的加速度变化。页面没有真正停帧，视觉上仍会像突然换挡。

同时，背景仿真每帧都会把速度和计数遥测写入 DOM `dataset`。Hero 内部的待机视差、扫光和打字机也在加载遮罩与页面牵引期间运行。移动端还需要合成长页面层，多个非必要更新会放大帧间隔波动。

## 实现

### 单一运动曲线

页面、水母和海流前沿的位移使用完整时长的 `cubic-bezier(0.12, 0, 0.88, 1)`。`impulse` 与 `tow` 继续作为叙事和调试阶段标记，但不再切换位移曲线。

钟形体、光环和触手仍保留蓄力与释放形变，因此动作不会退化成简单匀速平移。

### 自适应合成路径

- 桌面端继续移动单一 `.site-content` 图层，避免把导航和 Hero 拆成两个大图层。
- `767 px` 以下只移动导航与 Hero，并在牵引期间隐藏屏幕外章节的绘制。
- 深链接继续移动完整页面层，不应用首屏章节裁剪，原锚点与滚动位置保持不变。
- 动画完成后统一清理正文、导航和 Hero 的临时 `transform`、`clip-path` 与 `will-change`。

### 延后非必要动效

- 页面达到 `ready` 前暂停 `.site-content` 内的 CSS 循环动画。
- Hero 待机视差和打字机在收到 `homepage:experience-ready` 后才开始更新。
- 去除牵引水母整组的动态 `drop-shadow`，保留钟形体内辉光和局部外辉光。

### 遥测节流

背景逻辑和渲染仍按原有固定步进运行。仅将调试用 DOM 遥测写入限制到 `4 Hz`，避免每帧触发属性变更与字符串格式化。

## 性能证据

在关闭旧探针标签页后的前台浏览器中，高频读取 Hero 位置：

| 场景 | 有效位置帧 | p95 帧间隔 | 最大帧间隔 | 超过 24 ms |
| --- | ---: | ---: | ---: | ---: |
| 1440 x 900 / WebGPU / 最终结果 1 | 136 | 19 ms | 34 ms | 2 |
| 1440 x 900 / WebGPU / 最终结果 2 | 136 | 20 ms | 32 ms | 2 |
| 390 x 844 / WebGPU / 最终结果 1 | 136 | 19 ms | 31 ms | 1 |
| 390 x 844 / WebGPU / 最终结果 2 | 136 | 21 ms | 31 ms | 4 |

移动端优化前记录约为 100 个有效位置帧、`p95 31 ms`、最大 `47 ms`。最终四次采样均无反向位移，遥测写入约为 9 次，而旧桌面基线约为 138 次。

## 范围与降级

- 不修改背景实体规则、海豚路径、水母仿真、固定时间步、内容结构或外部链接。
- WebGPU、WebGL2 与 static 共用相同的页面位移曲线。
- `prefers-reduced-motion` 继续使用短淡入，不播放完整牵引。
- 未修改 `D:\project\blog`。
