# v0.15 整页物理牵引

## 问题

v0.14 延长了开场时间，但仍只分别移动导航、Hero 文案和视觉舞台。前景水母、海流线和正文使用不同的位移轨迹，因此视觉上仍是水母独自上升，页面随后出现，不具备明确的牵引关系。

深链接刷新会进一步暴露这个问题。浏览器定位到 `#contact` 等区块后，当前视口内的正文没有作为完整页面参与牵引，区块自身的滚动显现逻辑还可能与开场编舞竞争。

## 设计原则

- 水母、触手、页面前沿和完整 `[data-site-content]` 共用同一段垂直位移。
- 页面依靠真实位置变化进入，不使用透明度伪装位移。
- 水母触手末端始终接近页面前沿，主牵引阶段两者保持固定距离。
- 动画只改变 `transform` 与 `opacity`；正文裁切边界在开场期间保持固定，不逐帧修改布局属性。
- 低动态偏好继续跳过完整装置，只执行短淡入。

## 编舞

正常路径分为五段：

1. `arrival`：水母从视口下方游入并停在页面前沿上方。
2. `tension`：触手伸展，海流前沿从底部出现。
3. `bearing`：页面、水母和前沿共同移动 `4vh`，使用 `cubic-bezier(0.45, 0, 0.55, 1)` 表达张力建立。
4. `tow`：页面从 `92vh` 平滑移动到 `0`，水母同步从 `64vh` 移动到 `-28vh`，统一使用 `cubic-bezier(0.45, 0, 0.18, 1)`。曲线起点和终点速度均接近零。
5. `release`：页面停稳后海流前沿退场，随后恢复滚动与交互。

主牵引名义时长为 `2100 ms`，张力承载为 `580 ms`。实测完整正常编舞约为 `5.2 s`。故障保护路径使用相同空间关系和较短时长，不再退回到 Hero 子元素动画。

## 深链接与区块显现

开场开始时记录当前 `scrollY`，并将其转换为正文容器的静态 `clip-path` 上边界。正文整体上移时，裁切边界随容器一起移动，因此刷新 `#contact` 时不会把前一个区块带入视口，当前区块会从页面前沿下方完整进入。

`SectionTransitions` 延后到 `homepage:experience-ready` 后初始化。初始化时先根据最终视口位置写入可见状态，再启用普通滚动进退场，避免开场期间隐藏正文或在完成瞬间闪烁。

## 状态与清理

- `loading`、`ambient` 和 `entering` 阶段锁定页面滚动。
- 正文保持 `inert` 到 `ready`，牵引中不能误触链接和按钮。
- 完成后移除正文的 `transform`、`clip-path`、`opacity` 和 `will-change` 临时样式。
- `data-choreography-phase` 新增 `bearing` 与 `release`，继续保留总时长诊断。

## 范围

- 不修改页面正文、信息架构、主题配色和背景生态。
- 不修改海豚、水母和静物的固定步进逻辑。
- 不修改 `D:\project\blog`。
- 姓名、人像、简历、邮箱和未完成证据继续保持明确占位。
