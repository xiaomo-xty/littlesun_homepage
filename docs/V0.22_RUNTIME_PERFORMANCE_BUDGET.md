# v0.22 Runtime Performance Budget

## Goal

Keep the space-ocean background expressive without making decorative rendering a prerequisite for reading the homepage.

## Review Findings

- The static, reduced-motion, and Save-Data paths hydrated the full React + Three/WebGPU island before returning early.
- The reveal gate could wait up to `4800 ms` for the first GPU frame even though the complete page content was already server-rendered.
- Full quality sampled about 300 points against 19 local lights every rendered frame, or roughly 5,700 source-distance checks per frame.
- Ribbon positions/colors and particle colors uploaded dynamic buffers on every display refresh.
- High-refresh screens repeated CPU dolphin deformation and GPU submission above the simulation's fixed `60 Hz` rate.
- A full-viewport `backdrop-filter` continuously composited above the animated canvas.
- A runtime change to `prefers-reduced-motion` did not stop the ambient RAF loop.

## Decisions

### Conditional runtime loading

`AmbientWorldLoader.astro` renders the existing static ocean as SSR markup and evaluates a small policy module before hydration. The React + Three/WebGPU runtime is dynamically imported only when:

- `ambient` is not `static`;
- `prefers-reduced-motion` is not enabled;
- `Save-Data` is not enabled.

The loader is `1.35 KB gzip` in the v0.22 production build. The deferred Three/WebGPU and ambient chunks total about `205.4 KB gzip` and are absent from the initial HTML dependency list.

### Independent reveal

The reveal choreography starts from the SSR static ocean after its existing minimum wait. WebGPU initialization runs independently and crossfades through the existing canvas/fallback transition when ready. A slow or failed GPU backend no longer adds a separate `4800 ms` wait before the choreography.

### Split update budgets

- simulation: fixed `60 Hz` with accumulator and interpolation;
- display submission: capped near `60 FPS` on high-refresh screens;
- local-light colors and flow ribbon geometry: `20 Hz` full, `15 Hz` balanced;
- DOM telemetry: `4 Hz`;
- primary entity, jelly, dolphin, and particle positions: rendered with the existing interpolation path.

Local-light checks now reject distant sources with squared distance before using `sqrt`. Light samples are cached between detail refreshes. Ribbon geometry/color uploads and particle color uploads follow the detail rate, while particle matrices continue to update on rendered frames.

### Composition and motion preference

The full-screen postprocess keeps its tint and vignette but no longer applies `backdrop-filter`. Runtime reduced-motion changes stop the ambient RAF and reveal the static ocean; restoring motion resumes from a cleared accumulator.

## Verification

- `bun test`: 43 passed, 0 failed.
- `bun run check`: 0 errors, 0 warnings, 0 hints.
- `bun run build`: 2 routes generated.
- Production HTML contains the lightweight loader and does not directly reference the AmbientWorld or Three/WebGPU chunks.
- Render-cap tests produce 60 rendered frames for a 60 Hz source and 59-61 frames for 120/144 Hz sources over one second.
- Static/runtime policy tests cover default, WebGPU, WebGL2, explicit static, reduced-motion, and Save-Data paths.

## Deferred Work

- A shader or storage-buffer dolphin deformation path is not justified until a real trace shows the CPU mesh update remains dominant after this budget change.
- A spatial light grid is deferred because cadence reduction and squared-distance rejection remove most of the current work with much less complexity.
- Browser frame-time numbers must be captured again after a controllable local browser session is available; this document does not invent a new p95 result.
